# План реализации — трекер привычек (Telegram Mini App)

## Технологический стек

- **Frontend (Mini App):** React + TypeScript, Vite, Tailwind CSS, Telegram WebApp API (`@telegram-apps/sdk-react` или `telegram-web-app.js`)
- **Backend:** Node.js + TypeScript, Fastify (REST API), `grammy` для бота
- **БД:** PostgreSQL + Prisma ORM (миграции, типизация)
- **Хостинг:** Timeweb Cloud (VPS или managed Postgres), деплой из GitHub через git push / CI
- **Платежи:** ЮKassa (подключаем после оформления самозанятости; код оплаты пишем сразу, но с флагом отключения)
- **Репозиторий:** GitHub (монорепо: `apps/web`, `apps/api`, `apps/bot` или `server/` + `web/`)

## Архитектура

```
telegram-miniapp (React SPA)
        │ HTTPS + initData (подпись проверяется на сервере)
        ▼
   Fastify API ──────► PostgreSQL (Prisma)
        │
        └──► grammy bot (webhook на тот же API или отдельный процесс)
              ├─ напоминания (cron)
              ├─ ежедневные сообщения с картинкой персонажа
              └─ библиотека сообщений 1–180 день
```

Аутентификация: валидация `initData` от Telegram на сервере (HMAC), выдача своего JWT/сессии. Токен бота — только на сервере.

## Этап 1 — Фундамент (онбординг)

1. Инициализация репозитория, монорепо, ESLint/Prettier, tsconfig
2. PostgreSQL + Prisma: схема БД (см. ниже)
3. Fastify API: health-check, auth через initData
4. Mini App: подключение к Telegram WebApp, экран загрузки
5. Онбординг (пошаговый wizard):
   - форма обращения (откуда пришёл, кодовое слово, источник)
   - выбор персонажа (робот/кот)
   - имя трека (название привычки/цели)
   - привычка: две планки (цель + минимум)
   - расписание (дни недели, время)
   - напоминания (вкл/выкл, время)
6. Бот: `/start` → deep-link в Mini App, приветствие

## Этап 2 — Главный цикл

1. Отметки выполнения привычки в одно касание (swipe/button)
2. Начисление XP, монет, очков развития — только на сервере, идемпотентно
3. Пять стадий развития персонажа (эволюция по XP-порогам)
4. Энергия дня + вечерняя вылазка (бонус за выполнение)
5. Экраны: «Мой путь», календарь отметок, пауза привычки, выходные/пропуски
6. Питомец и бадди — опциональные, можно отложить

## Этап 3 — Бот и удержание

1. Приветствие и «письмо основателя»
2. Утреннее и вечернее сообщение с сгенерированной картинкой персонажа
3. Библиотека сообщений по дням 1–180 (контент-массив в БД/JSON)
4. Напоминания по расписанию привычки (cron-очередь)
5. Заморозка серии (streak freeze)

## Этап 4 — Анализ и доказательства

1. Сравнение недель, статистика по привычке
2. «Мои доказательства»: карточки для сторис (генерация изображения)
3. Рекомендации по правилам (простые эвристики на сервере)

## Этап 5 — Деньги

1. Модель подписки: free-режим + Pro 199 ₽/мес, 7 дней доступа
2. ЮKassa: платёж, webhook, отмена автопродления (подключение после самозанятости)
3. Feature-flag `PAYMENTS_ENABLED` — код готов, но выключен до ключей
4. Админка (простая, отдельный раздел API + экран): источники, когорты, выручка

## Этап 6 — Социальное (после запуска трафика)

1. Лента бадди по привычке и городу (согласие на видимость, фото)
2. Приглашения с наградой (реферальные ссылки/коды)
3. Защита: только по согласию, 18+, жалобы

## Этап 7 — Игра глубже

Магазин за монеты, комната кота / база робота, яйцо, клубы, «Планы», группы.

## Этап 8 — Аудит перед запуском денег

Разовый аудит кода живым разработчиком (прод-готовность, безопасность платежей).

## Схема БД (первая версия, Prisma)

- `User` — telegramId (unique), username, firstName, city, birthDate?, consent flags
- `Track` — userId, name, type (habit/goal), status (active/paused)
- `Habit` — trackId, target1, min1, target2, min2 (две планки), schedule (json), reminderTime
- `Entry` — userId, habitId, date, value, note, energyUsed
- `Character` — userId, type (robot/cat), stage (1–5), xp, level
- `Wallet` — userId, coins, gems?, streak, streakFreezeCount
- `Subscription` — userId, plan, status, expiresAt, providerId (ЮKassa)
- `Onboarding` — userId, referralCode, source, codeWord, completedAt
- `MessageLog` — userId, dayNumber, sentAt (библиотека 1–180)
- `BuddyProfile` — userId, visible, city, habitId, photoUrl (этап 6)

## Порядок запуска (под ролик)

**MVP к первому ролику:** Этапы 1–2 + минимум этапа 3 (напоминания) + Этап 5 с включённой оплатой (после самозанятости). Остальное — по мере трафика.
